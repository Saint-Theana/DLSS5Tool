# P0 原版参考项目同机对照 · 2026-10-20

## 结论

**本机参考基线同样能复现持续私有内存增长，尚未发现可直接移植的根治补丁。**
Veyra 1.4.4 的 NR、D3D12 Video SR，以及原始 standalone 的 NR 均出现增长。
standalone 使用的 NR 运行库与本项目相同；原版 Veyra 的外部 ETW 计数还复现了
`NvMessageBus.dll + 0x251510` 的大量短线程。此次对照加强了共同 NVIDIA 环境／运行库
触发路径的证据，尚未完成无覆盖层或其他官方驱动版本的因果对照，P0 保持部分完成。

## 范围与来源

- RTX 4070 SUPER、驱动 617.42、64 GiB RAM，同一台 Windows 机器。
- Veyra 是仓库已有的 **1.4.4 原版便携包**，主程序 SHA256 与原包 manifest 一致：
  `92ac81b14ab050895b33fd2a822c179f65c4a42bd89c6c00772b89c5684d7121`。
  为隔离配置、日志，原样复制主程序、必要 DLL、shader 和选定运行库到本任务目录；
  没有修改其源码或 PE。运行前后全部所选二进制／shader 哈希一致。
- Veyra 选择社区 RTX40/50 NR，运行库 SHA256 为
  `984bee0f775c277d5829b8fd6775d53a7b0f75396c852b3aaf06a18375f81014`。
- standalone 直接调用既有 `tmp/dlss5standaloneV2/dlss_engine.py` 的 `Live`，仅将日志路径
  指向任务目录。原 host DLL SHA256 为
  `9ec879388e573bebbf7886dccbdc885641d945420fdf4bb80bac6c657094160c`；
  NR DLL 与本项目一致，均为
  `ceb6432f6fbdf44d886014bcd47241932bf8b67439feef9bbdd0961436662650`。
- 合成图片为 640×360 SDR。Veyra NR 保持同尺寸，Veyra Video SR 实际输出 3840×2160；
  本项目与 standalone NR 均为 640×360。不同路径／运行库／尺寸之间不比较吞吐或增长率优劣。
- Veyra 的 Video SR 使用直接 D3D12 NGX Reserved16，实际加载驱动 NGX 及其 VSR 模型；
  未将目录中存在 `nvngx_vsr.dll` 等同于进程实际加载了它。
- 没有取得可运行的原版 Magpie；本机固定源码之外未找到其主程序，官方 Release API 本次返回
  HTTP 404。**本轮没有 Magpie 实机结果，也没有验证 Veyra 最新 2.x。**

## 同一进程的测量

外部每约 0.5 秒采样私有提交、工作集、句柄与进程树，PID 加创建时间核对身份，持有进程句柄
防止身份复用。树总量用于安全停止；下表增长率只取明确的处理进程，不合入 conhost、
Python 启动器、更新器或无关后台应用。

Veyra 排除最初 20 秒，截止到正常关闭请求；standalone 排除首帧后的 10 秒，截止到
`idle-end`。以前后各五分之一采样的中位数及其中位时间差计算斜率。资源退休后的下降不混入
观察窗口；原始关停后曲线仍保留。

| 路径 | 观察安排 | 私有提交分窗差 | 增长率 MiB/分钟 | 处理及退出 |
| --- | --- | ---: | ---: | --- |
| Veyra，全增强关闭 | 图片保持 60 秒 | +0.039 MiB | +0.072 | 正常关闭，无回收 |
| Veyra NR | 图片处理后保持 180 秒 | +96.58 MiB | +45.18 | 已创建 Feature18 并进入呈现；关停超时后回收 |

以上为有限窗口复现，**均不作为五分钟／三十分钟平台验收**。关闭增强的短测稳定也不外推为
小时级通过。不同轮次斜率变化，不能据此称某个宿主更优或已经改善。原 P0 门槛保持不变。

## 短线程的独立证据

原版 Veyra NR 的独立 30.032 秒 ETW 采集：

- 核对 PID `19724`、创建时间 `134369465797654344`，只保留该进程的计数与入口地址。
- **79,046 次线程创建，79,047 次退出**；退出多一次可由窗口开始前已存活的线程解释。
- 所有已计数入口均落在 `NvMessageBus.dll + 0x251510`。用模块清单的实际基址及原文件 PE
  `SizeOfImage` 核实地址范围，未使用“最近的前一个模块”猜测归属。
- 事件丢失、缓冲丢失、schema 和入口地址查询错误均为零。
- 计数器运行在外部独立进程，没有向 Veyra 注入 DLL；临时 ETW 会话结束后关闭，最终查询无本任务
  跟踪会话残留。首次普通权限失败保留；提权采集未修改驱动、注册表或服务。
- 初次自检把采集线程本身计入，得到 51／50，保持失败记录。排除采集线程后，50 个测试线程
  的最终自检为 **50 次创建／50 次退出**，无丢失或 schema 错误。

standalone 的进程内无挂钩通知计数也记录到相同偏移的大量创建／退出。此项存在计数 DLL，
与 Veyra 的纯外部证据明确区分。本项目本轮只取得一组进程内快照，不能从该快照推导短线程增速。

覆盖层 `nvspcap64.dll` 同时出现在稳定的 Veyra 全关闭基线和增长的增强路径中；
`nvcuda` 与 `NvMessageBus` 在增强路径中出现。**模块存在性不足以单独归因**。
此前 [驱动 184 字节持续分配栈](P0_NATIVE_ALLOCATION_20261020.md) 与此次线程证据相符，
但本轮未对每一块增长分配逐项归因，也未证明它就是原用户整机冻结的完整原因。

## 失败与限制

- Veyra 隐藏运行时自带 smoke 计时没有完成退出。首次短测保留超时失败；后续使用外部计时
  向本任务窗口发送正常关闭。关闭增强的基线正常结束，增强路径开始释放后仍超时，因此只回收
  本次创建且身份已核实的进程，**不将强制回收后的退出码 0 当成成功**。
- standalone 也在 `close()` 阶段超时。一次逐进程回收返回 Access denied，随后所属 Job 关闭后
  所有已知进程对象均已退出；原始失败和回收记录保留。
- 早期 standalone pilot 没有记录实际 Python worker PID，因此不用于正式内存斜率比较。
- Veyra NR 180 秒的早期自动结果曾把关停后的下降混入曲线；最终汇总依据原始样本严格截止到
  `normal-close.json`，原始误导性字段保留但不采用。
- 本项目的新一轮 NR 自然退出，所有参考测试最后均无本任务已知进程残留。个别短测有时间重叠，
  内存按精确身份区分；未据此比较性能或认定其他应用完全排除为触发条件。

## 对后续修复的影响

1. 本机原版参考不能提供“换上游宿主即稳定”的证据；原始 standalone 同 NR 运行库也复现，
   原版 Veyra 的另一套 D3D12 实现复现了共同线程入口。
2. 下一步优先形成**有效无覆盖层／插件环境对照**，再对一个明确的官方驱动候选做单变量比较；
   同时保留当前最小复现、线程／分配栈和模块身份，便于与 NVIDIA 缺陷核对。
3. Veyra 的退全屏保护及重开进程续导仍可作为恢复设计参考，但不能据此宣称消除持续增长。
   现有项目保护、NR 连续历史和画质合同保持；本轮没有新增定时重建 NR 等产品行为。

运行及哈希证据见 [汇总](p0-upstream-comparison-20261020/summary.json)。脚本为
`scripts/verify_upstream_p0.py`、`scripts/native_external_thread_activity.cpp` 与
`scripts/summarize_upstream_p0.py`，对应构建命令和自检保留在归档。本轮未运行全量回归，
没有修改生产实现、运行库、系统设置，也没有提交、打包或发布。
