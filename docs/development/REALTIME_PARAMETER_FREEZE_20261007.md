# 实时参数面板卡死诊断（2026-10-07）

## 结论

打开画面内参数面板确实会导致当前实时宿主停止出帧并异常退出，不只是光标隐藏。
根因是独立宿主漏适配了参数文案的 Windows 资源加载路径。初次只做诊断；
用户随后授权修复，已完成修复、宿主重建与本地安装，验证记录见文末。

## 代码链路与边界

`parameters` → `ScalingRuntime::InvokeOverlayAction` → `OverlayDrawer::_DrawEffectParameters`
→ `_InitEffectParameterValues` → `EffectParameterLocalization::Localize`。

`third_party/realtime/magpie/src/Magpie.Core/include/EffectParameterLocalization.h:26`
直接调用 `ResourceContext::GetForViewIndependentUse`，随后读取语言及 `Magpie/Resources`。
即使 Bilinear 的参数列表为空，仍然会先调用资源接口。

`scripts/prepare_realtime_build.py` 已替换主界面的资源加载和语言获取，但没有适配这个参数
本地化头文件。本地最小测试确认第一条资源调用在当前系统/未打包执行环境中即会异常终止。
未采集原生调用栈，因此不声称已排除所有其他问题；修复后仍需要真实窗口验收。

当前宿主没有启用 `isParameterFocusSwitchingEnabled`，不应把未启用的 Edit/Preview
焦点切换逻辑当作本次故障原因。本轮完全不使用 NR，不能归因于 AI 推理或强度大小。
未直接测量光标异常恢复，不能声称鼠标路径已经验证。

## 修复实现与验收

- `prepare_realtime_build.py` 生成独立参数本地化适配，从现有资源表读取显示文案；不再调用
  `ResourceContext` / `ResourceLoader`，缺少翻译保留原文。仍不修改第三方源文件或 shader 参数。
- `RealtimeClient` 采用有界异步写队列，Tk 不再同步写/flush 宿主 stdin。独立安全线程注册
  Ctrl+Alt+F10；宿主不重复注册该键。请求停止/退出后约 2 秒未完成会终止该 Popen 进程句柄；
  管道写阻塞另有 3 秒期限。无新帧的静态内容不会被当作卡死。
- 安全线程在持有输入的宿主退出后解锁光标区域、调用系统光标恢复；不对闲置宿主的退出
  干扰其他应用鼠标。重复停止不延长期限；原生停止状态同样有期限；异常退出和恢复期间的
  紧急停止均取消自动恢复，避免重新进入全屏。恢复 API 失败有可见提示。
- 主界面提供常驻退出/保护状态，底栏停止按钮附快捷键；原生画面使用无输入区域的常驻提示，
  不占用点击，也不要求先展开参数面板。退出保护线程独立于 Tk 和原生渲染，
  但不是系统/驱动彻底失去响应时的保证；最后退路仍是 Windows 安全界面。
