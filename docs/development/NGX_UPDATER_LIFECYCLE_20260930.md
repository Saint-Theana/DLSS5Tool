# NGX updater 生命周期实测 — 2026-09-30

## 结论

确认本程序的 DLSS 工作进程会启动多个 `nvngx_update.exe`。本机完整测试中，
7 次初始化分别观测到 5 个更新器，共 35 个，同时峰值为 5 个；每轮回到 0，
未复现更新器持续堆积或应用退出后残留。

因此“重复启动”已复现，“大量进程长期不退出”尚未复现。此前仅凭代码和旧研究
日志将反馈直接称为缺陷，证据不足；不能把本机成功退出推广为所有用户都不会残留。

## 环境与范围

- RTX 4070 SUPER；NVIDIA 驱动 617.14；Windows；现有 `.venv` Python 3.13。
- 使用当前源码的真实 `ProcessLive`、v2 原生后端、`runtime/nvngx_dlssnr.dll`；
  两个 DLL 的 SHA-256 与本地 v2.3.3 lite 发行目录完全相同，未替换运行库。
- 无引导模式，合成 RGBA 图像，640×360 与 800×448；每个会话真实处理 3 帧，
  共 21 帧，输出形状与类型检查通过，相同尺寸重建后的输出 SHA-256 一致。
- 测试调用 GUI 使用的工作进程生命周期接口，没有点击 GUI，也没有测试完整视频编码链路。
- 工作进程创建及帧处理等待上限在探针中收窄为 30 秒；不修改产品源码或用户设置。

## 方法与结果

外部监督进程每约 100 ms 使用 Windows Toolhelp 枚举进程，记录 updater 的
PID、父 PID、创建时间及可执行文件路径，并追踪本次测试的后代关系。基线为 0。

| 操作 | 实测结果 |
| --- | --- |
| 首次创建 DLSS 会话 | 5 个 updater，短时间内自行退出 |
| 连续 5 次切换尺寸 | 5 个不同的 DLSS 工作进程；每次 5 个 updater，每轮均回到 0 |
| 单独改变 style | DLSS 工作进程 PID 不变，未观测到额外 updater |
| 关闭后重开 | 新建工作进程，再出现 5 个 updater，随后回到 0 |
| 最终关闭 | 0 个 updater；等待 10 秒仍无残留 |
| 测试应用进程退出 | 外部继续观察 20 秒，无残留 |

35 个 updater 均为此次测试创建的后代，直接父 PID 与 7 个 DLSS 工作进程
对应，每个父 PID 下均为 5 个。路径均为 NVIDIA 驱动目录中的 `nvngx_update.exe`。
完整测试成功退出；残留为 0，因此无需强制终止任何 updater。

100 ms 轮询存在漏掉极短进程的可能，计数是**观测数量**。观测存活区间最大约
0.813 秒，不是精确进程运行时长；本测试不证明更新器成功联网或完成了更新。

## 限制与下一步

没有模拟网络异常、更新服务器不可达、冷缓存，也没有覆盖其他驱动、显卡和
用户选择的其他运行库。仓库中的 Streamline 探针结果不能替代正式应用的复现。

当前 `ProcessLive` 清理只回收工作进程本身，仍缺少 updater 后代的明确生命周期
管理；但本次未证实该缺口已经造成持续残留。建议先取得反馈用户的程序版本、
显卡/驱动、进程文件路径以及退出程序后是否残留的信息，再验证对应条件。
若确认残留，优先限定到本程序创建的进程树进行回收；不按名称全局终止更新器，
也不直接套用实验探针的“禁止一切子进程”，后者可能影响推理附加组件。
