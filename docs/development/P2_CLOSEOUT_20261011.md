## 新验收工具

- `scripts/realtime_p2_probe.py`：只选自己创建的窗口，串行运行矩阵；记录宿主/运行库哈希、
  实际计数、原生初始化、HDR 诊断及整卡采样。失败、无出帧、超时、无生成帧、
  光流质量未确认、仅配置 HDR 而无 FP16 证据，均不能判通过。
- `scripts/realtime_test_source.cpp`：有时限的自有 SDR/scRGB 图案窗口，带高于1和有符号线性值；
  可枚举 DPI/逻辑适配器 LUID。CMake 目标 `realtime_test_source` 默认不加入普通构建。
- `scripts/realtime_window_probe.py`：新增必填隔离输出目录、指定宿主、独立宿主状态、
  自有 HDR 源/跨屏移动、可选截图、异步整卡采样、超时保护和清理。
  跨屏场景在创建 Tk HWND 前声明 PerMonitorV2，避免150%下的坐标虚拟化产生假阳性。
- `RealtimeClient(state_root=...)` 仅为明确调用者提供隔离；普通主应用路径不变，外部预设不能注入此路径。

## 复验方法

先读仓库卫生守则、登记任务并检查磁盘空间。所有 `--output` 必须是新的目录，不覆盖旧报告。
GUI/WGC 探针需要正常交互桌面；沙箱不能查询捕获服务时按权限流程重跑，不静默换捕获方式。

```powershell
.venv/Scripts/python.exe -B scripts/realtime_p2_probe.py --output tmp/<task>/inventory --inventory-only
.venv/Scripts/python.exe -B scripts/realtime_p2_probe.py --output tmp/<task>/matrix --runtime-directory <已有SR-FG目录>
```

原生测试源用 VS2022 x64 CMake 配置 `native/realtime`，指定本机 `.venv/Scripts/python.exe`，
构建目录和 `REALTIME_OUTPUT_DIR` 都放新任务目录；仅构建 `--target realtime_test_source`。
随后运行：

```powershell
.venv/Scripts/python.exe -B scripts/realtime_p2_probe.py --output tmp/<task>/display --display-only --source-exe tmp/<task>/build/Release/realtime_test_source.exe --runtime-directory <已有SR-FG目录>
.venv/Scripts/python.exe -B scripts/realtime_p2_probe.py --output tmp/<task>/summary --summarize tmp/<task>/matrix
```

`--case` 可选择单场景，`--soak-seconds` 可延长合成测试（默认180秒、上限1800秒），
但延长合成测试仍不能代替真实游戏长稳。

## 最后需要的用户验收

1. 指定一个允许测试的窗口化游戏与场景：游戏自身、仅捕获、NR、NR/SR/FG 四组，
   包括 Alt-Tab/暂停恢复和至少20分钟持续负载；看游戏帧率、P95/P99、功耗和拖影，不只看提交速率。
2. HDR 主屏肉眼检查亮部不过曝、暗部不抬灰、颜色不跳变；高速运动时文字/HUD 不异常拖影。
3. 若需要 OBS 共存，明确允许的场景与捕获方式；不自动读取或改动用户 OBS 配置。
4. 混合 DPI 与双物理 GPU 在相应环境补验；本轮不擅自改系统缩放，也不把逻辑适配器当双卡。

这些剩余条件属于 P2 实机验收边界，不是隐藏的“已完成”。P0/P1 原有游戏输入/反作弊等缺口也未自动关闭。
已安装宿主仍是 `local-validation-only`，公开分发审核与发行打包不因本次通过而解除。
